# 용어집

> 문서, 코드, 커밋 메시지, UI 문구는 이 용어만 쓴다.
> 새 용어가 필요하면 이 표에 먼저 추가한다.

## 제품

| 용어       | 식별자        | 뜻                                                            |
| ---------- | ------------- | ------------------------------------------------------------- |
| 항목       | item          | 저장한 링크 하나.                                             |
| 저장       | capture       | 링크를 항목으로 만드는 동작.                                  |
| 다이제스트 | digest        | 정해진 시각에 항목 몇 개를 보여주는 메시지 묶음.              |
| 한 입      | bite          | 지금 볼 항목 하나를 요청하는 동작 (`/bite`).                  |
| 먹기       | consume       | 항목을 봤다고 표시하는 동작.                                  |
| 미루기     | snooze        | 항목을 정한 날까지 숨기는 동작.                               |
| 뱉기       | discard       | 항목을 보지 않고 버리는 동작.                                 |
| 보관하기   | archive       | 오래 둔 항목을 다이제스트 후보에서 빼는 동작. 지우지 않는다.  |
| 되돌리기   | undo          | 마지막 처리 전 상태로 돌리는 동작.                            |
| 우선순위   | priority      | 🔥 높음(high) / 보통(normal) / 언젠가(someday).               |
| 재노출     | resurfacing   | 다음에 보여줄 항목을 고르는 규칙.                             |
| 원본 URL   | raw_url       | 사용자가 보낸 그대로의 URL.                                   |
| 정규화 URL | canonical_url | 중복 판단에 쓰는 URL. 추적 파라미터를 지우고 형식을 통일한다. |

## 항목 상태

| 용어 | 식별자    | 뜻                                                   |
| ---- | --------- | ---------------------------------------------------- |
| 쌓임 | inbox     | 다이제스트 후보.                                     |
| 미룸 | snoozed   | 기한까지 후보에서 빠진 상태.                         |
| 먹음 | consumed  | 먹기를 한 상태.                                      |
| 뱉음 | discarded | 뱉기를 한 상태.                                      |
| 보관 | archived  | 보관하기를 한 상태. 다시 공유하면 쌓임으로 돌아간다. |

"보여줌"은 상태가 아니다. 마지막으로 보여준 시각(`last_shown_at`)과 횟수(`shown_count`)로 기록한다.

## 개발 프로세스

| 용어      | 식별자        | 뜻                                                          |
| --------- | ------------- | ----------------------------------------------------------- |
| 등급      | tier          | 변경 크기와 위험도. S / M / L.                              |
| 의도      | intent        | 무엇을, 왜, 어떤 제약에서 바꾸는지 적은 문서.               |
| 스펙      | spec          | 요구사항, 시나리오, 결정 필요 항목을 적은 문서.             |
| 계획      | plan          | L 등급에서 바꿀 파일, 순서, 위험을 적은 문서.               |
| 시나리오  | scenario      | WHEN/THEN으로 쓴 동작 하나. ID를 붙이고 테스트 이름에 쓴다. |
| 결정 필요 | decision      | 사람이 골라야 하는 항목. 선택지와 추천을 함께 쓴다.         |
| 리뷰 묶음 | review bundle | PR 설명의 고정 형식. 요약, 가정·결정, 검사 결과.            |
| 대화 재생 | replay        | fixture를 재생해 만든 대화 기록.                            |
| fixture   | fixture       | 테스트에 쓰는 텔레그램 업데이트 JSON.                       |
